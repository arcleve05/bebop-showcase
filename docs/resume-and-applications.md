## Interview guide

**What did you build personally?** Multiple Selenium, Playwright and UFT test-automation frameworks in prior professional roles; Bebop's personal architecture and selected code mechanisms presented here. Be specific about which work was personally written, AI-assisted or reviewed when discussing authorship.

**How does Bebop support regulated delivery?** It illustrates general reliability patterns: input contracts, independent validation, evidence-bound policy decisions and operator-visible failures. It is not presented as an employer release platform.

**What did you test?** Malformed declarations, stale evidence, critical failures, clock boundaries, invalid or unauthorized upstream states and concurrent refresh behavior. Public CI verifies individual examples, not a production end-to-end platform.

**What is still private/experimental?** Private integrations, internal deployment topology, model weights, state histories and unfinished workflows. Some deployment integrations have only staged/mock validation.

**Why no public employer code?** Confidentiality, IP boundaries and responsible handling of data from regulated environments.
